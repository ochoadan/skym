## Attempt 1 — Injector startup failure

Command:

```powershell
.\local\t04-2\venv\Scripts\python.exe -u src/Community.AdapterLab/launch.py --pid 36780 --run-dir local/t04-2/run-001
```

File/live signature preflight passed. Stdout reported Python injection and the PID, then printed `0` and `pyMHF exiting`; process exit was 1. No probe-event or pyMHF runtime log was produced. NMS exited. Windows Application event 1000 at **17:47:00 local** records an NMS native fault, exception `0xc0000005`, unknown module. The earlier conversational description of cleanup closing the game was incomplete: the event log establishes a native fault as well. No adapter action or successful response is credited to this attempt.

Source review found Pymem returning a **local** module handle after remote DLL loading, which pyrun-injected used to compute a remote entry point. The corrected launcher resolves actual target module paths/bases and checks the native export before execution. Also moved to the official Python package and wrapped initial pyMHF imports in public prompt-toolkit dummy sessions in both processes. These corrections were applied together, so the exact cause of the original native fault remains unresolved. A separate non-TTY parent import had failed with `NoConsoleScreenBufferError`; dummy-session import independently passed.

The Python archive had SHA-256 `9AC15CFA6CAB1115C83D48F2AF55C554EFA4D1BB044BBC4AB1C9D17AD426E16C`; its extracted `python.exe` Authenticode status was `Valid`, signer Python Software Foundation. ## Result and limits

**T-04.2 passed for the narrow synchronous native-chat operation.** The real action/callback/visible response, repetition, menu/reload, behavior disable, restart-based removal, second attached process and final settings/save recovery were verified. There were **three attachment attempts: one native startup failure and two successful attached sessions**. This satisfies the selected small input/presentation/recovery outcome; it does not complete all R-012–R-020 or full E-02/E-03. No live unload was attempted. M-02 remains unachieved because there is no service round trip.

Unimplemented or unmeasured: explicit startup/playable/menu lifecycle interface, live hook unloading, location/transform access, travel, two-hour stability/overhead, a typed external communication boundary, arbitrary custom game objects, noncompliant-client enforcement, native multiplayer admission, and platform save/cloud isolation. Callback string pointers are not retained and presentation is synchronous; asynchronous server replies require another validated presentation mechanism. The upstream execution console is development tooling and does not satisfy R-019.

Next: T-04.3 must first provide a bounded typed external request/reply path and a lifecycle-safe asynchronous presentation operation, carrying forward relevant R-015/R-019 work. Do not call the current native buffer from a worker or retain its pointer after the parse callback. Longer E-03 stability/performance work remains open. The lab ended with the original settings restored and no game/injector process or developer listener left running.
